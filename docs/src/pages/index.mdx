## Overview

Each component creates a canvas in the DOM. Each canvas is transferred to a shared worker, which renders the shaders using one WebGL context on an `OffscreenCanvas` and presents frames to the component canvases without involving the main thread. Each component has its own shaders, uniforms, frame rate, and buffers.

## Installation

Install the package in a React project. React 17 or later is required.

```bash
npm install react-offscreen-webgl
```

The package is alpha software and its API may change. The browser must support Web Workers, OffscreenCanvas, and WebGL.

## Quick start

Give the component a sized parent and a GLSL fragment shader. The canvas fills its parent.

```tsx
import { OffscreenWebGL } from 'react-offscreen-webgl';

const shader = `
  precision highp float;
  uniform vec2 u_resolution;

  void main() {
    vec2 uv = gl_FragCoord.xy / u_resolution;
    gl_FragColor = vec4(uv.x, uv.y, 0.0, 1.0);
  }
`;

export default function App() {
	return (
		<div style={{ width: 400, height: 400 }}>
			<OffscreenWebGL fragmentShader={shader} />
		</div>
	);
}
```

You can also load a shader with `fragmentShaderURL`. URL paths beginning with `/` resolve from the site origin, so include your base path when deploying under a subdirectory. Shader and URL props are read during initialization; remount the component to replace them.

## Uniforms

Pass uniforms as top-level props. With TypeScript 5.4 or later, for a literal shader string, TypeScript infers names and checks values without a helper. Uniforms are optional; vector values must be tuples of the corresponding length. The component manages `u_resolution` in canvas pixels and updates it on resize.

```tsx
const colorShader = `
  precision highp float;
  uniform vec3 u_color;
  uniform float u_opacity;
  void main() { gl_FragColor = vec4(u_color, u_opacity); }
`;

// Correct
<OffscreenWebGL fragmentShader={colorShader} u_color={[1, 0.4, 0.2]} u_opacity={0.8} />;

// Type error: uniform with mismatched dimension
<OffscreenWebGL fragmentShader={colorShader} u_color={[1, 0.4]} u_opacity={0.8} />;

// Type error: uniform typo (u_color vs u_colour)
<OffscreenWebGL fragmentShader={colorShader} u_colour={[1, 0.4, 0.2]} u_opacity={0.8} />;
```

Inference supports `float`, `vec2`, `vec3`, and `vec4`, optional precision qualifiers, comma-separated declarations and comments. It combines the vertex shader and all literal fragment groups. Uniforms must start with `u_`. Source that is dynamic, fetched from a URL, exceeding the bounded parser budget (up to about 4,096 characters or 128 comment/declaration scan steps), contains a preprocessor directive or uses unsupported declarations (such as arrays, matrices, samplers or structs) falls back to broad `u_*` props; these cases do not get source-based type checking. Only float and float-vector values are supported by the renderer. Shader compilation and linking are still checked at runtime.

### Streaming mouse and scroll input

Create a stable stream for values that change frequently. Its initial values define the uniform names and scalar/vector shapes; `set` changes one value and `update` changes several together. These calls do not need a React render.

```tsx
import { useState } from 'react';
import { createUniformStream, OffscreenWebGL } from 'react-offscreen-webgl';

const mouseShader = `
  precision highp float;
  uniform vec2 u_resolution;
  uniform vec2 u_mouse;
  uniform float u_scroll;
  void main() {
    vec2 mouse = u_mouse / u_resolution;
    gl_FragColor = vec4(mouse, u_scroll, 1.0);
  }
`;

export function MouseShader() {
	const [stream] = useState(() => createUniformStream({ u_mouse: [0, 0], u_scroll: 0 }));
	return (
		<div
			style={{ width: 400, height: 400 }}
			onPointerMove={(event) => {
				const bounds = event.currentTarget.getBoundingClientRect();
				stream.set('u_mouse', [
					(event.clientX - bounds.left) * devicePixelRatio,
					(bounds.bottom - event.clientY) * devicePixelRatio,
				]);
			}}
		>
			<OffscreenWebGL fragmentShader={mouseShader} uniformStream={stream} refreshRate={60} />
		</div>
	);
}
```

Use `stream.set('u_scroll', progress)` for normalized scroll progress, or `stream.update({ u_mouse: [x, y], u_scroll: progress })` to publish a complete update. Updates with unchanged values are ignored. Stream values accept numbers and vectors of one to four numbers, as arrays or typed arrays such as `Float32Array`. Names and vector lengths are typed from the initial values, so `set` and `update` reject unknown names and wrong shapes at compile time, and throw at runtime. The managed `u_resolution` uniform cannot be streamed. Use a new stream to change the layout. Stream layouts are not checked against the shader source.

When `crossOriginIsolated` is `true` and `SharedArrayBuffer` is available, the component sends the buffer to the worker once when attaching the stream; changing `refreshRate` does not reattach it. Subsequent updates write shared memory without `postMessage`. The worker only uploads uniforms whose values changed. The worker samples complete snapshots on its frame loop and repaints changed streams at `refreshRate`, even without a worker callback. Intermediate updates can be skipped; streams represent the latest state, not an event queue. Atomic versioning prevents partially written vectors or multi-uniform updates from being applied. Existing worker callbacks see the sampled values before running, and can still call `paintCanvas()`.

Shared memory requires a secure context and cross-origin isolation. Configure your server to return these HTTP response headers for the page and worker resources:

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Cross-origin resources must also satisfy the embedder policy, and the `cross-origin-isolated` permissions policy must allow isolation. See the [HTML Standard's cross-origin isolation requirements](https://html.spec.whatwg.org/multipage/webappapis.html#cross-origin-isolated-capability). The library does not set these headers. Without isolation, if the browser cannot allocate or clone the buffer, or if the worker does not acknowledge it within one second, updates automatically use batched worker messages. Other worker errors put the component in its error state. The fallback coalesces pending values into one update and repaint per scheduled frame at `refreshRate`; it stops scheduling when there are no pending changes. Unmounting or replacing the stream cancels pending updates.

A stream can drive multiple canvases. Replacing or removing `uniformStream` disconnects the previous stream; removing it leaves the last applied values on the canvas. Unmounting disconnects the component. Keep each uniform in either a stream, props, or worker callbacks to avoid competing writes. This transport handles numeric uniforms; camera frames and media textures need a separate API.

## Worker callbacks

Callbacks receive the manager, frame count, and elapsed time in milliseconds. Call `paintCanvas()` to render a frame. The live example updates a time uniform this way.

```tsx
<OffscreenWebGL
	fragmentShader={shader}
	f_each_animate={(manager, frame, time) => {
		manager.updateUniform('u_time', time / 1000);
		manager.paintCanvas();
	}}
/>
```

<div className="callout"><strong>Keep callbacks self-contained.</strong> Functions are serialized and evaluated in the worker, so they cannot capture variables from their surrounding scope. Pass values through uniforms instead.</div>
</section>

## Multi-pass rendering

Pass nested arrays to `fragmentShader` or `fragmentShaderURL` to configure shader groups. Shaders within a group ping-pong through framebuffer objects; the final group renders to the canvas. All passes share the vertex shader.

```tsx
<OffscreenWebGL fragmentShader={[[firstPass, secondPass], [finalPass]]} />
```

## Limitations

- The component is browser-only. In an SSR framework, load it on the client (for example, a dynamic import with SSR disabled).
- Worker callbacks share WebGL state; restore state you change so other components are unaffected.
- Media and camera textures are not yet supported.
- The worker ships inside the package and starts from a `blob:` URL. With a Content Security Policy, allow `worker-src blob:`.
- The library requires the browser features listed below. The example needs WebGL enabled to render.
